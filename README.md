
# FoodVision Mobile

A mobile food classification application built with **React Native
(Expo)**, **FastAPI**, and an **EfficientNet-B0** model trained on
the Food-101 dataset, initially using 5 classes.

## 1. How it works

1.  The user selects an image in the mobile app.
2.  The app sends the image to the FastAPI API.
3.  The backend preprocesses the image and runs inference using
EfficientNet-B0.
4.  The API returns the predicted class and the prediction confidence.
5.  The app displays the result.

## 2. Supported classes

The model for this experiment was prepared for these 10 classes:


-   `hamburger`
-   `pancakes`
-   `pizza`
-   `steak`
-   `sushi`

The class order is important: it must match the order used
during training and the classifier's output. Refer to
`backend/models/efficientnet_b0/classes.json`.

## 3. Obtaining the trained model

The model weights are an artifact generated by the training notebook and
**should not be recreated manually**.

### Step 1 --- Train or run the notebook

Open `notebooks/classifierEfficientVit.ipynb` in Google
Colab and run the training and export cells. At the end, the notebook
should generate a file named:

`efficientnet_b0_food10.pth`

The notebook may also export `classes.json` and a ZIP file containing
the artifacts. The exact names depend on the export cell used.

### Step 2 --- Transfer to your computer

Transfer the `.pth` file (and `classes.json`, if generated
separately) from Colab to your computer. If the notebook generates a
ZIP file, extract it first. ### Step 3 --- Place the files in the correct folder

At the root of the `FoodVision-Mobile` repository, create the following folder
if it does not already exist:

``` text
backend/models/efficientnet_b0/
```

Place the following files there:

``` text
backend/models/efficientnet_b0/
├── efficientnet_b0_food10.pth
└── classes.json
```

On Windows, you can open the project folder in File Explorer and
copy the files to this path. You can also create the folder
from the terminal at the project root:

``` powershell
New-Item -ItemType Directory -Force backend/models/efficientnet_b0
```

Ensure the file names and extensions are correct. Avoid names
like `efficientnet_b0_food10.pth.pth` or
`efficientnet_b0_food10 (1).pth`.

### Step 4 --- Configure the backend

The inference code should load the checkpoint using a path
relative to the project folder, for example:

``` python
from pathlib import Path

PROJECT_ROOT = Path(__file__).resolve().parents[1]
MODEL_PATH = (
PROJECT_ROOT
/ "models"
/ "efficientnet_b0"
/ "efficientnet_b0_food10.pth"
)
```

This example assumes the code is located at `backend/app/predictor.py`.
Verify the path if your backend structure differs.

Loading the checkpoint must be compatible with the format actually
saved by the notebook. In this project, the expected checkpoint contains,
among other fields, `model_name`, `num_classes`, `class_names`,
`state_dict`, `image_size`, `mean`, and `std`. The backend must reconstruct the
EfficientNet-B0 with a 10-output classification layer and load the
`state_dict`.

### Step 5 --- Run and verify

Install the backend dependencies and start the API from the
`backend` folder:

``` bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Check the available endpoints, for example:

-   `GET /health` --- confirm that the API is active.
-   `POST /predict` --- send an image and receive the prediction.

Interactive API documentation is usually available at
`http://127.0.0.1:8000/docs`.

> These commands assume that `requirements.txt` includes FastAPI,
> Uvicorn, PyTorch, TorchVision, and the other dependencies used by
> the code.

## 4. GitHub and model size

`.pth` checkpoints can be large. To avoid issues with
GitHub's file limits, **do not automatically include the weights in the
standard Git repository**.

Recommended options:

1.  **GitHub Releases:** attach the checkpoint to a release and document
the download link in this section.
2.  **Git LFS:** use Git Large File Storage if you want to version control
the checkpoint.
3.  **External storage:** save the file in an accessible location and
document a stable link.

After choosing where to host the checkpoint, add the actual download URL
here and, ideally, the file's SHA-256 hash. Do not include a placeholder
link: the link should only be added after the model has actually been
published. The `.gitignore` can ignore weight files by default while keeping a
`.gitkeep` file to preserve the folder in Git:

``` gitignore
backend/models/**/*.pth
backend/models/**/*.pt
!backend/models/**/.gitkeep
```

If you decide to use Git LFS or attach the model to a Release, adjust this
rule according to your chosen strategy.

## 5. Limitations

This is an academic and portfolio prototype. The model only predicts the 5
listed classes; it should not be presented as a classifier for all
foods in the Food-101 dataset. The predicted confidence is not necessarily a
calibrated probability, and an image falling outside the known classes may
be incorrectly classified.
